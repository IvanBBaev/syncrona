now-sdk parity: SyncroNow AI covers the everyday ServiceNow SDK (`now-sdk`) workflow without giving up the file-based tier.

- `query <table>` reads records with the `now-sdk query` flags (all but `-s/--select` and `-a/--auth`) and JSON envelope; the table name must be letters, digits and underscores, and `--timeout` at least 1.
- `cicd <action>` drives `api/sn_cicd`: `run-suite`, `run-test`, `install`, `publish` and `rollback`, with exit codes 0 (pass), 1 (could not finish) and 2 (failures). `--progress-id` resumes waiting on a run that outlived `--timeout` without dispatching it again; `--json` prints a failure document (with the `progressId` to resume) when the run could not finish, and `--poll-ms` is kept between 250 and 60000.
- `fluent <action>` drives Fluent projects through the new optional `@syncrona/fluent` package (`@servicenow/sdk` is an optional peer, `~4.13`), reusing the syncrona credential store for Basic and OAuth profiles. `fluent init` writes a default project version (`0.0.1`) and the loaded SDK version into `package.json`, the CLI warns once when the SDK is outside `~4.13`, and `fluent install` refuses to prompt without a terminal or with `--json` (pass `--ci`).
- `push --create` / `--no-create` creates or adopts records for unmapped local files (also `createRecords` in `sync.config.js`). On a table outside the `sys_metadata` hierarchy, which has no `sys_scope` column, the idempotency lookup and the POST body leave the scope out, and `sys_choice` is matched on its natural key (`name`, `element`, `value`, `language`, `dependent_value`). `push --prune` deletes in-scope records whose tracked files git shows deleted. Prune refuses while a download is unfinished, when `sourceDirectory` is blank, missing or empty, and above 25 deletions or 20% of the manifest without `--allow-mass-delete`; under `--ci` it needs `--diff`, a path or that flag. A record the instance no longer has (404) is reported as unverified and keeps its manifest entry, and a table that is both pruned and created gets a rename warning. `push --create` refuses to adopt an instance record the manifest already tracks under another name, or one another candidate of the same run adopted, and `push --prune` holds the DELETE of a record whose sys_id the same run's creation plan matched (a rename, not a deletion) — in the dry run and the real run alike; a record renamed on the instance is picked up with `syncrona refresh`. Idempotency lookups read back the key columns and fail closed when one is missing or its value differs (including a case-only difference), the `sys_choice` natural key includes `dependent_value` (empty and missing match alike), a key value containing `^` cannot be created or adopted because encoded queries cannot escape it, and a flat-layout prune target such as `Foo~Bar~script.js` matches only the record `Foo~Bar`.
- While `cicd` or `sync_cicd_run` waits on a run, a poll that fails transiently (a network failure, 408, 425, 429 or a 5xx, including an OAuth token endpoint 5xx) is retried up to 3 times in a row, one `pollMs` apart and one request per poll on both sides, before the run is reported as could-not-finish (`incomplete`); any other poll error still ends the run at once. A network failure is judged by its code, its own or its cause's (a socket reset, a refused connection, an undici socket error or a timeout), so a client-side bug, a malformed HTTP answer or a rejected OAuth token is no longer retried as if the instance had not answered.
- With OAuth, a token endpoint that rejects the first token request costs one token request in the core CLI, as in `sync_cicd_run`; it used to force a second grant, and the request was never sent either way.
- `cicd` reports a progress poll answered with a client error (400, 401, 403, 404, ...) at once, naming the status and the `GET api/sn_cicd/progress/<id>` request, instead of the bare transport message; three transient failures in a row name the request too. A run that reaches `--timeout` while polls are still failing now ends with the timeout error (last status and last poll error) rather than the transport error, and every timeout says where to check the tracker on the instance and how to resume it with `--progress-id` (exit 1).
- `cicd` retries a progress poll answered with 408 (request timeout) like 429 and 5xx, and reports a 3xx answer (a 304, or a redirect the client did not follow, naming its `Location` when it has one) to a progress poll, the dispatch or the ATF result read as an unexpected 3xx answer, usually a proxy or an SSO/login gateway in front of the instance, with the text `sync_cicd_run` uses, instead of a client error or a bare "Request failed with status code 304"; it is not retried. An HTML page answered in place of JSON (a body starting with `<`; a JSON body is read as JSON whatever its content type says, as `sync_cicd_run` reads it) and a redirect loop end the run at once as a session/authentication redirect, instead of a missing `result` or a no-response poll that is retried. Its sn_cicd requests follow at most 20 redirects, the limit `sync_cicd_run`'s fetch has, so a redirect loop costs the same 21 requests on both sides.
- `cicd` and `sync_cicd_run` decide an ATF verdict from an allow-list: a suite passes only with status `success` or `success_with_warnings` and zero rolled-up failures and errors, and an unknown status or count is reported as could-not-finish (exit 1) rather than a pass. Resuming an ATF tracker with `--progress-id` as `install`, `publish` or `rollback` is refused.
- `sync_cicd_run` (and `cicd`, which shares the verdict) no longer reports a suite that executed zero tests as passed: a passing suite status with a stated success count of 0 (an empty suite, or every test skipped) is `failed` / exit 2 with "the suite ran no tests", and one whose success count is missing or unreadable is `incomplete` / exit 1. Resuming a successful tracker that links no ATF result as `run-suite` or `run-test` is refused as `incomplete` rather than read as a pass, and a failed or cancelled one is reported as ending before any test result rather than as failing tests.
- `cicd --progress-id` (and a `sync_cicd_run` resume) over an ATF tracker that ended in error or was cancelled before it linked a result now exits 2 / `failed` like the dispatched run, saying no test results were reported (and that an app-repo tracker would be resumed with its own action), instead of exit 1 with a resume-as-install hint.
- `cicd --progress-id` (and a `sync_cicd_run` resume) over a finished ATF tracker whose result answers 404 now says the progress id may belong to the other ATF kind (a suite run resumed as `run-test`, or the reverse) and names the action to resume it with, instead of an endless "re-run with --progress-id" hint.
- `cicd --json` documents carry a `verdict` (`passed`, `failed`, `no_tests`, `incomplete` when the run could not be followed to its end, `unknown` when the tracker finished but its ATF result was unreadable or unclear) and a `reason`, success and failure documents alike; the failure document keeps its `error` field.
- `sync_cicd_run` polls again on 408 and 425 like core, sends each sn_cicd request once (its poll loop owns the retries, so a persistent failure costs the same 3 requests as in core), and reports a 3xx answer as an unexpected 3xx answer (usually a proxy or an SSO/login gateway) instead of a failed request; it is not retried. An HTML page in place of JSON (a body starting with `<`) and a redirect loop are reported like core, as a session/authentication redirect that is not retried.
- `sync_cicd_run` ends every timeout like `cicd`: the message gives the budget in seconds, the last status (and the last poll error when polls were failing at the deadline, which now ends with the timeout rather than the transport error), where to check the tracker (its link, the dispatch answer's link, or `GET api/sn_cicd/progress/<id>`) and how to resume waiting with `progressId` and a larger `timeoutMs`.
- `sync_cicd_run` responses carry an additive `verdict` with the values `cicd --json` reports (`passed`, `failed`, `no_tests`, `incomplete`, `unknown`), so an `incomplete` outcome tells a run that could not be followed apart from a finished tracker whose ATF result was unreadable or unclear, and an additive `reason` with the values `cicd --json` reports, set in the same cases, in full and possibly over several lines; both are documented in the tool description, which also states that a rejected call (an unknown action, an invalid argument or a missing `confirmDestructive`) returns only an error text, with neither field.
- `run_workspace_command` now asks for confirmation before `cicd`, `dev`, `refresh`, `init --new`, `repair --apply` and every `fluent` action except `status`, `explain` and `types` (without `--out`).
- New MCP tool `sync_cicd_run` exposes the same `api/sn_cicd` actions to AI clients, gated by `confirmDestructive` with `dryRun` support and audit logging; it reports `succeeded` / `failed` / `incomplete` with the CLI exit code. An optional `progressId` resumes polling an `incomplete` run's tracker instead of dispatching new work.
- New MCP tool `sync_fluent_build` runs `fluent build` for a Fluent project inside the workspace through the optional `@syncrona/fluent` package, with the CLI's `frozenKeys` / `errorOnConflict` / `skipClean` flags, `dryRun` support and audit logging; it returns errors, warnings and output paths with the CLI exit code, and a structured error with the install hint when the package or `@servicenow/sdk` is missing (63 MCP tools). Errors and warnings are capped at 200 each (with counts and truncation flags), output listing does not follow symlinks, and a missing optional package is detected by the exact module name.
- `SN_MAX_RPS` lowers the 20 requests/second cap for the CLI and the MCP server (a whole number from 1 to 20; an invalid value is an error, never a silent full rate).
- `init --new --name` creates a new scoped application and binds the directory to it, writing an empty manifest with the new `scopeId` when the app owns no records yet (a later `refresh` keeps that `scopeId`); the existing-app check queries `sys_scope`, so a store app of the same scope is found too. `download` of an existing scope that owns no records still refuses instead of writing an empty manifest. A `refresh` of that empty manifest keeps it, reports at info level that the scope owns no records yet, and exits 0, so `dev` no longer logs an error on every interval; a manifest without a `scopeId` still refuses an empty discovery.
- `download <scope> --ci` for a scope that owns no records yet still refuses without prompting and exits 1, and the refusal now says so: a new scope has nothing to download until it owns a record, and `init --new` is the way to bind a scope that is still empty.
- Opt-in `dataModelTables` tracks data-model records (tables, columns, choices) as editable local files.
- With `dataModelTables` on, `download` and `refresh` fetch only the scope's `sys_choice` rows instead of the whole table.
- A `sys_properties` record of type `password` or `password2`, or whose type cannot be read, never has its `value` written to the working tree: not in its `.meta.json` sidecar, and not as a `value` field file from `includes` or the data-field fallback. That column is always fetched through the Table API so each record's type can be checked, and `refresh` reports withheld values at info level instead of marking the table incomplete.
- Dictionary `internal_type` values returned as `{ link, value }` references are read correctly: password, journal and other opaque columns stay out of sidecars, and script fields keep their file type instead of falling back to `.txt`.
- The data-field fallback (`SYNCRONA_DATA_TABLES`, `SYNCRONA_INCLUDE_DATA_FIELDS`) no longer writes password, journal, collection or image columns as `.txt` files.
- An `includes` entry no longer brings back a column whose dictionary type is never written to the working tree (password, password2, journal, collection, image); the column is dropped with a warning naming the table and column. If its dictionary type cannot be read, the column is kept and a warning says so.
- `init` applies the same `sys_properties` secret rule to the scoped endpoint's answer: governed values are re-read by sys_id through the Table API, so a password property's value is never written.
- Secret and unsafe columns are now decided in one place (`classifyColumn`) on every manifest path. An `includes` entry whose dictionary type is a credential, journal, collection or image type is dropped with a warning from the scoped-endpoint manifest too — on `init`, `refresh` and `download` — so its value is never written and never requested. An included column whose type cannot be read (no dictionary row, empty type, or a failed lookup) is kept and named in a warning, once per column per build. When the `sys_properties` re-read on `init` returns fewer rows than requested, a warning gives the count; `refresh` retries those records.
- `repair` no longer counts a value the secret rule withholds as a missing file, so it converges after a refresh, and `repair --apply` exits 1 with the remaining count when files are still missing after the re-download instead of reporting success.
- `repair --apply --prune` deletes only orphan files git holds committed and unchanged, so a new script or column not pushed yet is never lost; it refuses to prune outside a git repository or without a commit, and never prunes files of tables the manifest does not list.
- `repair --apply --prune` never deletes the files of a record awaiting `push --create` (a path `push --create` would create a record from), even when they are committed and unchanged; only a record the committed manifest tracked with a sys_id counts as the leftover of an instance record.
- `repair --apply --prune` finds the repository from the source directory even when `GIT_DIR` or `GIT_WORK_TREE` is exported, matches names macOS stores decomposed when `core.precomposeunicode` is set, and passes the paths to `git hash-object` on stdin, so no command-line length limit applies. A file git cannot read is kept with git's reason while the rest are still pruned. A refusal quotes git's own error, the prompt says git can restore the files, the run prints the `git checkout` command that does, and the last line no longer reports success while orphans are left in place.
- `repair` no longer mistakes directories named like `Object.prototype` members (`constructor`, `__proto__`, `toString`) for orphans.
- `repair --apply` re-fetches secret-rule values even when nothing else is missing, so a deleted non-secret `sys_properties.value` is restored while a password value stays withheld.
- `sync_fluent_build` is now classed as a mutating tool, so policy, preflight and the mutating audit trail apply to it; `dryRun` still returns the plan without loading the adapter. Its description states that the build runs the project's installed `@syncrona/fluent`/`@servicenow/sdk` and build-time code in the server process with the server's full environment, and that the `timeoutMs` budget cannot interrupt synchronous build work. An adapter resolved from the project whose real path leaves the workspace is refused with `FLUENT_ADAPTER_OUTSIDE_WORKSPACE`. Its input schema is unchanged, but the reclassification is client-visible under `requirePreflight` / `requireDryRun` policies — `TOOL_CONTRACT_VERSION` moves to 1.1.0.
- The `target`, `diff` and `updateSet` inputs of `sync_push` and the `diff` input of `sync_build` now reject a value that starts with `-`, so it cannot be read as a CLI flag. A git ref never starts with `-`; the legitimate values refused are a target path or an update-set name that does (a path can still be passed as `./-name`).
- `sync_fluent_build` no longer refuses an adapter hoisted above the workspace when the server's own install provides it (a server started in a monorepo package directory): an adapter the project resolves outside the workspace is still never loaded from there, and the call is refused with `FLUENT_ADAPTER_OUTSIDE_WORKSPACE` only when the server has no copy of its own; the refusal now says to start the server from the workspace root or pass `project:`. The workspace confinement compares canonical real paths, so a workspace path spelled in another letter case on macOS or Windows is no longer refused.
- `sync_fluent_build` takes the server's own adapter only from the server's `node_modules` ancestry: an adapter Node finds through `NODE_PATH` or a global folder (`~/.node_modules`, `~/.node_libraries`, `<prefix>/lib/node`) is refused with `FLUENT_ADAPTER_OUTSIDE_WORKSPACE` instead of being loaded as the server's install.
- A real `sync_fluent_build` run reports the adapter it loaded, in the response and the mutating audit: `adapter.source` (`project` or `server`), `adapter.path` (the real path of its package directory) and `adapter.version`. The field is additive and absent when no adapter was loaded.
- `sync_fluent_build` is exempt from the instance preflight that `enforcePreflightForMutations` (top-level or per environment) turns on: the build never calls the instance, so it is no longer refused when the instance is unreachable or its session scope or update set differs from the expected one. The tool policy and the mutating audit still apply, and an explicit `policy.tools.sync_fluent_build.requirePreflight: true` still preflights it.
- `syncrona fluent --dry-run` now fails wherever the real run would before printing the plan — `types --native` without a scope or project, and `install`/`move-to-app` without `--ci` under `--json` or without a terminal — and `--dry-run --json` prints the plan as JSON.
- A plain `fluent types --dry-run` reports the method the real run uses: it checks whether the adapter and `@servicenow/sdk` are installed (the same resolution the real run makes, without credentials or the instance) and reports the native generator when the real run would fall back to it, failing where that fallback would (no scope). A dry run of `install` or `move-to-app` refused without `--ci` now says to pass `--ci` to preview without a prompt, since a dry run changes nothing. `fluent install` and `fluent move-to-app` (and `types --native` when it reads the project's scope) refuse a `now.config.json` that cannot be read or parsed, naming the file, in the real run and the dry run alike; `install` and `move-to-app` also refuse one that sets no `scope` instead of prompting for an "(unknown scope)" or leaving the check to the SDK.
- `fluent --dry-run` of every action but `types --native` (`build`, `types --scripts`, `dependencies`, `transform`, `explain` and the rest) now checks that the adapter and `@servicenow/sdk` are installed, the same resolution the real run makes, and exits 1 with the install hint when one is missing instead of exiting 0 with a plan the real run cannot carry out. It still resolves no credentials and reaches no instance.
- `fluent types --native --table <names>` (and the plain `types --table` fallback) no longer reads the project's `now.config.json`, since the named tables make its scope unnecessary, so a malformed config no longer blocks it; the project is still used for the default output location.
- `fluent` reads `now.config.json` the way the SDK does where it matters for the scope: a leading byte-order mark, `//` and `/* */` comments and trailing commas are accepted (other JSON5 syntax is still refused, naming the file), and the scope is trimmed, so a whitespace-only `scope` counts as none and `install`/`move-to-app`/`types --native` refuse it instead of using it.
- A plain `fluent types` with an API-key or mutual-TLS profile now falls back to native generation when the SDK is not installed, as `--dry-run` reports, instead of refusing the profile before the fallback; with the SDK installed the profile is still refused.
- `download`/`refresh` of an existing scope that yields no tables no longer advises `syncrona init --new` (which refuses an existing scope and points back at `download`): it says to create a record in the scope, or to opt a default-excluded table in with `excludes: { <table>: false }` or `dataModelTables` (see `syncrona config show-defaults`). The `init --new` advice moves to the scope-not-found error, where it applies.
- `fluent types --native` generates a table `.d.ts` from `sys_db_object`, `sys_dictionary` and `sys_choice` without the SDK (inheritance through `extends`, choice columns as literal unions, deterministic sorted output) and works with every profile, API key and mutual TLS included. A plain `fluent types` still uses the SDK when it is installed and falls back to the native generator when it is not.
- Opt-in `dataModelLayout: "composite"` keeps a table, its columns and their choices as one byte-stable document (`data-model/<table>.json`); push stays diff-only and ordered table, columns, choices, and a workspace mixing both layouts is refused.
- `fluent explain [topic]` reads the documentation bundled with `@servicenow/sdk` offline (`--list` for the topic index, `--peek` for summaries), and `fluent move-to-app --ids <sys_id,...>` moves global records into a global application's Fluent project; it creates `sys_claim` records on the instance, so it confirms unless `--ci` (without a terminal or with `--json` it exits 1 asking for `--ci`) and supports `--dry-run`. It exits 2 when no record moved.
- New guide: `docs/MIGRATING_FROM_NOW_SDK.md`.
- `login`, `logout`, `instances` and `use` no longer print `Unknown log level "undefined"` on every run; these commands take no `--log-level` and use the default level, `info`.
- `login` with stdin that is not a terminal (a scripted login with every field from flags) no longer asks whether to switch the active instance: it keeps the current one and prints the `syncrona use <instance>` command that switches it.
- `cicd` error lines for a run that exits 1 now read `cicd <action> incomplete:` (or `result unknown:`), matching the `--json` verdict and `sync_cicd_run`'s outcome. They used to read `failed:`, which is exit 2's word — for example on an unknown `--progress-id`, which answers 404.
- `push --dry-run` and `deploy --dry-run` no longer refuse when your user's scope differs from the project's: they warn and preview anyway. A dry run never swaps scopes, even with `--scopeSwap`, because the swap writes your scope preference on the instance; the real run still refuses a mismatch.
- Not yet verified against a live instance: `push --create` / `--prune`, `cicd` (and `sync_cicd_run`), `init --new`, and the Fluent commands that reach the instance or the SDK (`fluent explain`, `fluent move-to-app`, `sync_fluent_build`). They are covered by tests against mocked responses only; try them on a development instance first.
- Records whose names collide on a case-insensitive or Unicode-normalising volume (`Util` and `util`) now get their own folders, `<name>_<sys_id>`, even when the manifest comes from the scoped endpoint. Before, they overwrote each other's files and a push could upload the wrong record. The names do not depend on record order, the CLI warns once per collision, and other records keep their folders. Upgrade: the first `refresh` or `download` renames a colliding record's folder when only that record used it, keeping local edits. A folder several records shared is left in place with a warning, and the records are downloaded fresh into their new folders; delete the old folder after review (`repair` lists it as orphans). See `docs/DATA_MODEL.md`, "Record folder names".
- Record names that no filesystem stores as written now get a storable folder name. A NUL or other control character is replaced with `_`. A name longer than 180 UTF-8 bytes is cut on a code point boundary and gets `_<8-hex SHA-256>` of the whole name, so it is unique and the same on every run. Before, such a record failed to download (`ENAMETOOLONG`, or a name cut at the NUL) and could not be pushed. Table, field, type and scope names with control characters or more than 255 bytes are refused like other unsafe segments. Upgrade: a checkout that stored a 181 to 255 byte name, or a name with a tab, has that folder renamed on the first `refresh` or `download`, keeping local edits. See `docs/DATA_MODEL.md`, "Record folder names".
- The dictionary `internal_type` is compared trimmed and lower-cased, so an `includes` column typed `Password2` is dropped like a `password2` one and never reaches a field file or sidecar. When the parent table hierarchy of a table cannot be read (a failed `sys_db_object` lookup, or no row because of an ACL), an included column the table inherits is still kept, but the warning now says the parent table hierarchy could not be read instead of reporting a missing dictionary row.
- A field file left behind by a column the manifest no longer lists (the `includes` type filter now drops it, or it left `includes`) is now reported. `refresh` and `download` warn once, naming each such file, that it is no longer synced and can be deleted. Nothing is deleted automatically; `repair` lists the files as orphans. See `docs/DATA_MODEL.md`, "What a record contains".
- A refused path segment now says why. `Refusing to download` and `Refusing to write` errors name path traversal (and the directory it would escape), a control character or lone surrogate with its code point, or a segment over 255 UTF-8 bytes with its length. Before, every refusal said the name "would escape" its directory, even when it was only too long or held a control character.
- `push --create` no longer creates a duplicate record when the idempotency lookup answers without a result list (an object, `null`, or no `result`). Before, that answer read as "no match", so the record was planned as a create, or POSTed again after a timed-out create. Now the lookup fails: the record is reported as failed, its table is listed in `failedTables`, and nothing is adopted or created.
- Pushing an ATF step (`sys_atf_step`) to an instance whose Sincronia server app has no `pushATFfile` route now says so. The error names the prefixes it tried and the HTTP status, instead of only "Request failed with status code 400". When `push --create` has already inserted the step and only its script could not be sent, the error says the record was created and gives its sys_id, so it no longer reads as never created.
- `init --new` no longer creates a second application for a scope that is already in use when the `sys_scope` lookup answers without a result list, or finds the scope but cannot read its sys_id (for example because an ACL hides it). Before, both answers read as "the scope is free" and a `sys_app` was POSTed. Now `init --new` stops with an error and creates nothing.
- `cicd` no longer waits past `--timeout`. The pause between progress polls, including the retry pause after a failed poll, is cut short at the deadline, and `--poll-ms` is capped at 60000 as `sync_cicd_run` already caps it. Before, `--timeout 1 --poll-ms 600000` slept ten minutes before reporting the timeout.
- `fluent --json` now keeps stdout to the one JSON document. Every log line, including the SDK's own messages and the notice that `types` fell back to native generation, goes to stderr. Before, info lines could reach stdout ahead of the JSON, so `syncrona fluent ... --json | jq` failed to parse.
- `fluent types --native` now escapes a parent table name it could not read, and the table's own name, inside the generated doc comment. Before, a `super_class` name holding `*/` ended the comment early, and the rest of the name was written into the `.d.ts` as code.
- `fluent types --native` now compiles when a grandchild table overrides the choices of a column that its parent already overrides. The grandchild is compared against the parent's narrowed column, and omits it from the parent when the two differ. Before, it was compared against the original column, so the `Omit<>` was missing and `tsc` failed with TS2430.
- `jira-logout` no longer reports a removal that did not happen. A profile with no stored credentials is reported as such, and a credential file that could not be deleted (for example, a permission error) fails the command with exit code 1 instead of being reported as removed. `jira-logout --all` also fails, naming the profiles still on disk.
- `jira` without a key now reads a project key with an underscore from the branch name: `MY_PROJ-12` resolves to `MY_PROJ-12` instead of `PROJ-12`, an issue of another project. A snake_case branch-type word in front of the key (`feature_abc-123`) is still dropped.
- `docs` now renders record, file, table and scope names as data. A `|` or a line break in a name no longer breaks the Markdown table, and `<` or a backtick no longer turns the name into HTML or breaks out of its code span. On regeneration, the generated block is found only by start and end markers on lines of their own, ending at the first end marker after the start, so a marker quoted in a name or in manual notes no longer cuts the block short or duplicates it.
- `jira` now strips terminal control characters (keeping tabs and line breaks) from the issue text it prints, so an escape sequence or carriage return in a summary, field or comment can no longer recolour, rewrite or hide the surrounding output. `--json` output was already escaped.
- `refresh` now reports a table that the instance returned nothing for as incomplete. A table that the instance answered for with no records, as it does for a table it skips on a 400, 403 or 404, is named in a warning and left for the next run. Before, its missing files were silently not downloaded, and the refresh reported success.
- `download` now resumes only from a checkpoint recorded against the same instance. The checkpoint stores the instance it was downloaded from, and a checkpoint from another instance, or one written before instances were recorded, is treated as stale. Before, a download interrupted on one instance and rerun against another skipped the tables already completed on the first one.
- `repair --apply --prune` no longer deletes a field file whose name differs from the manifest only in case, such as `Script.js` for field `script`. Refresh already treats that file as the field's local copy and never writes a second one. Before, prune counted it as an orphan and deleted the only copy.
- `repair --apply --prune` now checks the git evidence again after the confirmation is answered. A file edited while the prompt was open is kept and named in a warning, because git no longer holds it unchanged. Before, the evidence gathered before the prompt was trusted, and the edit was deleted along with the file.
- A `login` that switches authentication method now removes the previous method's `SN_*` keys from the workspace `.env` (for example `SN_AUTH_METHOD` and `SN_API_KEY` after switching from an API key to Basic). Before, the new keys were added next to the old ones, so the next command still authenticated with the old method and its secrets instead of the credentials `login` had just verified.
- `logout` and `use` now reduce an instance given as a full URL (for example one pasted from the address bar, `https://dev12345.service-now.com/now/nav/ui/...`) to its bare host, the same way `login` does. Before, they kept the path, so `logout` reported "No stored credentials" and left the login on disk, and `use` exited with "No saved credentials".
- `syncrona mcp` now merges into an MCP client config saved with a UTF-8 byte order mark (as Windows editors such as Notepad write it), keeping the other servers registered there. Before, the BOM made the file read as malformed, and it was replaced with a config that held only the `syncrona` entry.
- The once-a-day update check now creates `~/.syncrona` private to the user (mode `0700`), the same mode the credential store uses. Before, on a first run the check created the directory with the default mode (usually `0755`) before any login, and the credential store kept it, so other local users could list what it held.
- The update check now runs again when its cache records a last check in the future (a clock that once ran ahead, or a cache copied from another machine). Before, it waited until that moment arrived, so a clock that was a year ahead once stopped the "update available" notice for a year.
- `dev` now drops a queued change once its file is deleted. Before, a file whose push had failed stayed queued after it was deleted, so every automatic retry failed on it; when it was the stale copy named by an `Ambiguous push` error, deleting it as the error advises left the whole queue stuck, and every later save failed with it until `dev` was restarted.
- The MCP health endpoint (`SYNCRONA_HEALTH_HTTP_PORT`) now closes at once on shutdown, even when a client is in the middle of a request. Before, a client that sent a partial request and went quiet kept the endpoint open until the HTTP header timeout, so the server did not exit on SIGTERM until then.
- A tool metric sample recorded after the MCP server was killed mid-write is now kept. Before, the next sample was appended onto the partial line the killed write left in `metrics.jsonl`, so both shared one unparseable line and the new sample was dropped from the restored metrics on every later start.
- An MCP audit record written after another writer was killed mid-append is now kept on a line of its own. Before, it was appended onto the partial line left in `audit.log`, so the record became part of one unparseable line and was lost, although the write reported success.
- A command the MCP server runs (the `syncrona` CLI tools, `run_workspace_command`, the startup scope pull) now gets an empty stdin, so a child that asks for input (a confirmation prompt, `npx` offering to install a package) sees end-of-input and fails at once. Before, stdin was an open pipe nobody wrote to, so such a child waited and the tool call only answered when its timeout killed it.
- Output the MCP server captures from a command it runs keeps a multi-byte UTF-8 character (Cyrillic, accented or CJK text, emoji) intact when the character arrives split across two chunks. Before, each chunk was decoded on its own, so such a character came back as two U+FFFD replacement characters.
- A ServiceNow read the MCP session and metadata tools make (`sync_list_scopes`, `sync_list_update_sets`, `sync_get_session_context`, `sn_list_metadata_records`, the startup scope pull) now fails with the HTTP status and the instance's message when the instance rejects it. Before, a 401, 403 or 5xx read as an empty table, so an expired password was reported as "Scope not found", "Could not find sys_user", "no x_* scopes found" or zero records.
- `sync_set_scope`, `sync_set_update_set` and `sync_prepare_session` now fail with the HTTP status when the instance rejects the user-preference write that switches the scope or update set, or the creation of a missing update set. Before, a 403 on that write was ignored, so the tool reported the scope or update set as changed while the session stayed where it was.
- `sync_check_instance_capabilities` now keeps its `scope` argument inside the `sinc/getManifest/<scope>` route segment by URL-encoding it. Before, the scope was interpolated as-is and fetch resolved its dot segments, so a value such as `../../../now/table/sys_user` turned the read-only manifest probe into a POST that created a record through the Table API, and a scope with `?`, `#` or a space probed the wrong endpoint.
- `sync_search_semantic_index` and `sync_symbol_cross_reference` now rebuild their index when a source file is added with an older timestamp than the index (moved in with `mv`, copied with `cp -p`, unpacked from an archive). Before, the staleness check read only a shrinking file count as a change, so such a file raised the count without a newer mtime and its symbols stayed missing until a tool happened to invalidate the index.
- `sync_search_semantic_index` and `sync_symbol_cross_reference` called after the semantic index was invalidated (by a push, a file write or another tool) now wait for a build that starts after that invalidation. Before, a call that arrived while an older build was still running shared that build and returned symbols from before the change.
- `sync_cicd_run` now retries a transient failure (a 5xx, 408, 425, 429 or a dropped connection) on the ATF result read of a finished `run-suite` or `run-test`, up to the same 3 attempts one `pollMs` apart as a progress poll, as core does. Before, that read was sent once, so a single 502 or socket reset after the run turned a known pass or failure into `incomplete`.
- `sync_generate_release_notes` and `sync_export_update_set` now fail with the HTTP status when the instance rejects the lookup of the update set named by `updateSetName`. Before, a 401, 403 or 5xx on that lookup read as no rows, so an expired password was reported as "Update set not found".
- `sync_export_update_set` with `writeFiles: true` now saves the export only when the instance answered it with a 2xx. Before, a rejected export (a 403, a 5xx) wrote the error page to `.syncrona-mcp/exports/<name>.xml`, overwriting an earlier good export of the same update set with a file that is not update-set XML.
- `sync_validate_before_push` now lists a requested table it cannot read in `unknownTables` and withholds `ready` and `validated` when there is one, as `sn_search_scripts` does. Before, such a name was dropped in silence, so `tables: ["sys_ui_action"]` validated no script and still answered `ready: true`.
- `sync_compare_instances` now lists a requested table it cannot read in `unknownTables` and reports `summary.complete: false` when there is one. Before, such a name was dropped in silence, so `tables: ["sys_ui_action"]` compared nothing and still answered `complete: true`.
