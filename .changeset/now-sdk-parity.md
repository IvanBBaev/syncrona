now-sdk parity: SyncroNow AI covers the everyday ServiceNow SDK (`now-sdk`) workflow without giving up the file-based tier.

- `query <table>` reads records with the `now-sdk query` flags (all but `-s/--select` and `-a/--auth`) and JSON envelope; the table name must be letters, digits and underscores, and `--timeout` at least 1.
- `cicd <action>` drives `api/sn_cicd`: `run-suite`, `run-test`, `install`, `publish` and `rollback`, with exit codes 0 (pass), 1 (could not finish) and 2 (failures). `--progress-id` resumes waiting on a run that outlived `--timeout` without dispatching it again; `--json` prints a failure document (with the `progressId` to resume) when the run could not finish, and `--poll-ms` is floored at 250.
- `fluent <action>` drives Fluent projects through the new optional `@syncrona/fluent` package (`@servicenow/sdk` is an optional peer, `~4.13`), reusing the syncrona credential store for Basic and OAuth profiles. `fluent init` writes a default project version (`0.0.1`) and the loaded SDK version into `package.json`, the CLI warns once when the SDK is outside `~4.13`, and `fluent install` refuses to prompt without a terminal or with `--json` (pass `--ci`).
- `push --create` / `--no-create` creates or adopts records for unmapped local files (also `createRecords` in `sync.config.js`). On a table outside the `sys_metadata` hierarchy, which has no `sys_scope` column, the idempotency lookup and the POST body leave the scope out, and `sys_choice` is matched on its natural key (`name`, `element`, `value`, `language`, `dependent_value`). `push --prune` deletes in-scope records whose tracked files git shows deleted. Prune refuses while a download is unfinished, when `sourceDirectory` is blank, missing or empty, and above 25 deletions or 20% of the manifest without `--allow-mass-delete`; under `--ci` it needs `--diff`, a path or that flag. A record the instance no longer has (404) is reported as unverified and keeps its manifest entry, and a table that is both pruned and created gets a rename warning. `push --create` refuses to adopt an instance record the manifest already tracks under another name, or one another candidate of the same run adopted, and `push --prune` holds the DELETE of a record whose sys_id the same run's creation plan matched (a rename, not a deletion) — in the dry run and the real run alike; a record renamed on the instance is picked up with `syncrona refresh`. Idempotency lookups read back the key columns and fail closed when one is missing or its value differs (including a case-only difference), the `sys_choice` natural key includes `dependent_value` (empty and missing match alike), a key value containing `^` cannot be created or adopted because encoded queries cannot escape it, and a flat-layout prune target such as `Foo~Bar~script.js` matches only the record `Foo~Bar`.
- While `cicd` or `sync_cicd_run` waits on a run, a poll that fails transiently (no response, 429 or a 5xx) is retried up to 3 times in a row before the run is reported as could-not-finish (`incomplete`); any other poll error still ends the run at once.
- `cicd` reports a progress poll answered with a client error (400, 401, 403, 404, ...) at once, naming the status and the `GET api/sn_cicd/progress/<id>` request, instead of the bare transport message; three transient failures in a row name the request too. A run that reaches `--timeout` while polls are still failing now ends with the timeout error (last status and last poll error) rather than the transport error, and every timeout says where to check the tracker on the instance and how to resume it with `--progress-id` (exit 1).
- `cicd` and `sync_cicd_run` decide an ATF verdict from an allow-list: a suite passes only with status `success` or `success_with_warnings` and zero rolled-up failures and errors, and an unknown status or count is reported as could-not-finish (exit 1) rather than a pass. Resuming an ATF tracker with `--progress-id` as `install`, `publish` or `rollback` is refused.
- `sync_cicd_run` (and `cicd`, which shares the verdict) no longer reports a suite that executed zero tests as passed: a passing suite status with a stated success count of 0 (an empty suite, or every test skipped) is `failed` / exit 2 with "the suite ran no tests", and one whose success count is missing or unreadable is `incomplete` / exit 1. Resuming a tracker that links no ATF result as `run-suite` or `run-test` is now refused as `incomplete` whatever the tracker's status, instead of reporting a failed app-repo run as failing tests.
- `run_workspace_command` now asks for confirmation before `cicd`, `dev`, `refresh`, `init --new`, `repair --apply` and every `fluent` action except `status`, `explain` and `types` (without `--out`).
- New MCP tool `sync_cicd_run` exposes the same `api/sn_cicd` actions to AI clients, gated by `confirmDestructive` with `dryRun` support and audit logging; it reports `succeeded` / `failed` / `incomplete` with the CLI exit code. An optional `progressId` resumes polling an `incomplete` run's tracker instead of dispatching new work.
- New MCP tool `sync_fluent_build` runs `fluent build` for a Fluent project inside the workspace through the optional `@syncrona/fluent` package, with the CLI's `frozenKeys` / `errorOnConflict` / `skipClean` flags, `dryRun` support and audit logging; it returns errors, warnings and output paths with the CLI exit code, and a structured error with the install hint when the package or `@servicenow/sdk` is missing (63 MCP tools). Errors and warnings are capped at 200 each (with counts and truncation flags), output listing does not follow symlinks, and a missing optional package is detected by the exact module name.
- `SN_MAX_RPS` lowers the 20 requests/second cap for the CLI and the MCP server (a whole number from 1 to 20; an invalid value is an error, never a silent full rate).
- `init --new --name` creates a new scoped application and binds the directory to it, writing an empty manifest with the new `scopeId` when the app owns no records yet (a later `refresh` keeps that `scopeId`); the existing-app check queries `sys_scope`, so a store app of the same scope is found too. `download` of an existing scope that owns no records still refuses instead of writing an empty manifest. A `refresh` of that empty manifest keeps it, reports at info level that the scope owns no records yet, and exits 0, so `dev` no longer logs an error on every interval; a manifest without a `scopeId` still refuses an empty discovery.
- `download <scope> --ci` for a scope that owns no records yet still refuses without prompting and exits 1, and the refusal now says so: a new scope has nothing to download until it owns a record, and `init --new` is the way to bind a scope that is still empty.
- Opt-in `dataModelTables` tracks data-model records (tables, columns, choices) as editable local files.
- With `dataModelTables` on, `download` and `refresh` fetch only the scope's `sys_choice` rows instead of the whole table.
- A `sys_properties` record of type `password` or `password2`, or whose type cannot be read, never has its `value` written to the working tree: not in its `.meta.json` sidecar, and not as a `value` field file from `includes` or the data-field fallback. That column is always fetched through the Table API so each record's type can be checked, and `refresh` reports withheld values at info level instead of marking the table incomplete.
- Dictionary `internal_type` values returned as `{ link, value }` references are read correctly: password, journal and other opaque columns stay out of sidecars, and script fields keep their file type instead of falling back to `.txt`.
- The data-field fallback (`SYNCRONA_DATA_TABLES`, `SYNCRONA_INCLUDE_DATA_FIELDS`) no longer writes password, journal, collection or image columns as `.txt` files.
- An `includes` entry no longer brings back a column whose dictionary type is never written to the working tree (password, password2, journal, collection, image); the column is dropped with a warning naming the table and column. If its dictionary type cannot be read, the column is kept and a warning says so.
- `init` applies the same `sys_properties` secret rule to the scoped endpoint's answer: governed values are re-read by sys_id through the Table API, so a password property's value is never written.
- Secret and unsafe columns are now decided in one place (`classifyColumn`) on every manifest path. An `includes` entry whose dictionary type is a credential, journal, collection or image type is dropped with a warning from the scoped-endpoint manifest too — on `init`, `refresh` and `download` — so its value is never written and never requested. An included column whose type cannot be read (no dictionary row, empty type, or a failed lookup) is kept and named in a warning, once per column per build. When the `sys_properties` re-read on `init` returns fewer rows than requested, a warning gives the count; `refresh` retries those records.
- `repair` no longer counts a value the secret rule withholds as a missing file, so it converges after a refresh, and `repair --apply` exits 1 with the remaining count when files are still missing after the re-download instead of reporting success.
- `repair --apply --prune` deletes only orphan files git holds committed and unchanged, so a new script or column not pushed yet is never lost; it refuses to prune outside a git repository or without a commit, and never prunes files of tables the manifest does not list.
- `repair --apply --prune` never deletes the files of a record awaiting `push --create` (a path `push --create` would create a record from), even when they are committed and unchanged; only a record the committed manifest tracked with a sys_id counts as the leftover of an instance record.
- `repair` no longer mistakes directories named like `Object.prototype` members (`constructor`, `__proto__`, `toString`) for orphans.
- `repair --apply` re-fetches secret-rule values even when nothing else is missing, so a deleted non-secret `sys_properties.value` is restored while a password value stays withheld.
- `sync_fluent_build` is now classed as a mutating tool, so policy, preflight and the mutating audit trail apply to it; `dryRun` still returns the plan without loading the adapter. Its description states that the build runs the project's installed `@syncrona/fluent`/`@servicenow/sdk` and build-time code in the server process with the server's full environment, and that the `timeoutMs` budget cannot interrupt synchronous build work. An adapter resolved from the project whose real path leaves the workspace is refused with `FLUENT_ADAPTER_OUTSIDE_WORKSPACE`. The input schema is unchanged, but the reclassification is client-visible under `requirePreflight` / `requireDryRun` policies — `TOOL_CONTRACT_VERSION` stays 1.0.0 pending an owner decision.
- `sync_fluent_build` no longer refuses an adapter hoisted above the workspace when the server's own install provides it (a server started in a monorepo package directory): an adapter the project resolves outside the workspace is still never loaded from there, and the call is refused with `FLUENT_ADAPTER_OUTSIDE_WORKSPACE` only when the server has no copy of its own; the refusal now says to start the server from the workspace root or pass `project:`. The workspace confinement compares canonical real paths, so a workspace path spelled in another letter case on macOS or Windows is no longer refused.
- `sync_fluent_build` is exempt from the instance preflight that `enforcePreflightForMutations` (top-level or per environment) turns on: the build never calls the instance, so it is no longer refused when the instance is unreachable or its session scope or update set differs from the expected one. The tool policy and the mutating audit still apply, and an explicit `policy.tools.sync_fluent_build.requirePreflight: true` still preflights it.
- `syncrona fluent --dry-run` now fails wherever the real run would before printing the plan — `types --native` without a scope or project, and `install`/`move-to-app` without `--ci` under `--json` or without a terminal — and `--dry-run --json` prints the plan as JSON.
- A plain `fluent types --dry-run` reports the method the real run uses: it checks whether the adapter and `@servicenow/sdk` are installed (the same resolution the real run makes, without credentials or the instance) and reports the native generator when the real run would fall back to it, failing where that fallback would (no scope). A dry run of `install` or `move-to-app` refused without `--ci` now says to pass `--ci` to preview without a prompt, since a dry run changes nothing. `fluent install` and `fluent move-to-app` (and `types --native` when it reads the project's scope) refuse a `now.config.json` that cannot be read or parsed, naming the file, in the real run and the dry run alike; `install` and `move-to-app` also refuse one that sets no `scope` instead of prompting for an "(unknown scope)" or leaving the check to the SDK.
- `fluent types --native` generates a table `.d.ts` from `sys_db_object`, `sys_dictionary` and `sys_choice` without the SDK (inheritance through `extends`, choice columns as literal unions, deterministic sorted output) and works with every profile, API key and mutual TLS included. A plain `fluent types` still uses the SDK when it is installed and falls back to the native generator when it is not.
- Opt-in `dataModelLayout: "composite"` keeps a table, its columns and their choices as one byte-stable document (`data-model/<table>.json`); push stays diff-only and ordered table, columns, choices, and a workspace mixing both layouts is refused.
- `fluent explain [topic]` reads the documentation bundled with `@servicenow/sdk` offline (`--list` for the topic index, `--peek` for summaries), and `fluent move-to-app --ids <sys_id,...>` moves global records into a global application's Fluent project; it creates `sys_claim` records on the instance, so it confirms unless `--ci` (without a terminal or with `--json` it exits 1 asking for `--ci`) and supports `--dry-run`. It exits 2 when no record moved.
- New guide: `docs/MIGRATING_FROM_NOW_SDK.md`.
- Not yet verified against a live instance: `push --create` / `--prune`, `cicd` (and `sync_cicd_run`), `init --new`, and the Fluent commands that reach the instance or the SDK (`fluent explain`, `fluent move-to-app`, `sync_fluent_build`). They are covered by tests against mocked responses only; try them on a development instance first.
- Records whose names collide on a case-insensitive or Unicode-normalising volume (`Util` and `util`) now get their own folders, `<name>_<sys_id>`, even when the manifest comes from the scoped endpoint. Before, they overwrote each other's files and a push could upload the wrong record. The names do not depend on record order, the CLI warns once per collision, and other records keep their folders. Upgrade: the first `refresh` or `download` renames a colliding record's folder when only that record used it, keeping local edits. A folder several records shared is left in place with a warning, and the records are downloaded fresh into their new folders; delete the old folder after review (`repair` lists it as orphans). See `docs/DATA_MODEL.md`, "Record folder names".
- Record names that no filesystem stores as written now get a storable folder name. A NUL or other control character is replaced with `_`. A name longer than 180 UTF-8 bytes is cut on a code point boundary and gets `_<8-hex SHA-256>` of the whole name, so it is unique and the same on every run. Before, such a record failed to download (`ENAMETOOLONG`, or a name cut at the NUL) and could not be pushed. Table, field, type and scope names with control characters or more than 255 bytes are refused like other unsafe segments. Upgrade: a checkout that stored a 181 to 255 byte name, or a name with a tab, has that folder renamed on the first `refresh` or `download`, keeping local edits. See `docs/DATA_MODEL.md`, "Record folder names".
