### Patch Changes

- 2dbbf1c: - `build` reports the compile errors and warnings the SDK only logs. The SDK's `Orchestrator.build` returns `{ success: false, diagnostics: [] }` when the project has TypeScript errors and prints them to the console instead, so `syncrona fluent build --json` and the MCP `sync_fluent_build` tool showed a failed build with `errorCount: 0`. The engine now hands the SDK a project logger that forwards to the console but holds back error and warn messages during a build and returns them (colour codes stripped, without the SDK's "Found N diagnostic error(s)" summary when the diagnostics themselves are listed). Structured diagnostics still win when the SDK returns them; the held-back log is then printed as before.
- 8465f1a: `compileFluentProject` now reports key conflicts the way the SDK build does: a record defined more than once (same table and sys_id, from different calls) and an explicit `$id` used for records of different tables are errors listing each definition's path and line. A build with conflicts returns no `keysText`, since the keys registry would otherwise hand the shared `$id` to whichever table claimed it last.
- e02c1ef: - The native Fluent compiler checks the table of a `Record()` and every column its `data` sets against the project's tables and dictionary types, warning about the names it cannot find. An unknown table is reported once per call.
- f88a98e: Docs: package READMEs drop the legacy upstream references. The fluent README states the ServiceNow SDK licensing notes inline, the MCP server examples use a neutral `x_acme_*` scope, and the repository `NOTICE` now carries only the project copyright and the ServiceNow trademark notice.

## 1.1.0

### Minor Changes

- fb75e72: `syncrona fluent` accepts a mutual-TLS client certificate (`SN_CLIENT_CERT` / `SN_CLIENT_KEY`) with a Basic or OAuth profile instead of refusing it. Core hands the TLS settings to the Fluent engine as `tls`, the OAuth token request presents the certificate, and the engine installs a TLS-configured fetch dispatcher for the duration of each instance-side action, restoring the previous one afterwards. `SYNCRONA_CA_BUNDLE` and `SYNCRONA_TLS_REJECT_UNAUTHORIZED` now apply to the Fluent tier as well. API-key profiles are still refused.
